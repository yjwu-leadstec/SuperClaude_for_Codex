# /sc:design

## When to Use

Use this skill when the user invokes `/sc:design`.
Also activate when:
- Architecture planning and system design requests
- API specification and interface design needs
- Component design and technical specification requirements
- Database schema and data model design requests

## Aliases

- `/sc:design`
- `sc:design`
- `design`

## Codex Behavior

- Reasoning effort: **high**
- Web search: **optional**

## Workflow

1. Analyze
2. Plan
3. Design
4. Validate
5. Document

## Safety

Do not write or modify code unless the user explicitly requests it.
Ask for user confirmation before changing scope beyond the original request.

## Output

Return a structured **architecture spec** containing:
- System overview
- Components
- Interfaces
- Data flow
- Deployment

## Completion

After completing `/sc:design`, suggest relevant follow-up commands.
